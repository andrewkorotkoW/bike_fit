# Bike Fit Analyzer

Определение углов посадки на велосипеде по фото/видео сбоку, сравнение с
референсными диапазонами по дисциплине и выдача рекомендаций по регулировкам
в миллиметрах.

## Установка

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

Тесты (на синтетических точках, MediaPipe не нужен):

```bash
python -m unittest discover -s tests
```

## Запуск

```bash
# веб-интерфейс
streamlit run app.py

# CLI по одному фото
python -m bikefit.cli --photo bdc.jpg --profile road_endurance \
    --calib 812,640,905,760,172.5 --out annotated.jpg --json report.json

# по видео — надёжнее: кадры НМТ/ВМТ находятся автоматически
python -m bikefit.cli --video ride.mp4 --profile road_race --step 2

# с геометрией конкретного велосипеда
python -m bikefit.cli --photo bdc.jpg --bike rose_backroad_ml --calib 120,700,1170,712,1048.74

# PDF-отчёт (в веб-интерфейсе — кнопка «Скачать отчёт PDF» под результатами)
python -m bikefit.cli --photo bdc.jpg --pdf report.pdf
```

`--height/--inseam/--arm/--shoulders` (см) — антропометрия райдера: стартовая
высота седла по inseam (LeMond 0.883×, Hamley 1.09×), ширина руля по плечам,
проверка роста против диапазона рамы. Inseam — внутренняя длина ноги: от пола
до промежности босиком.

`--bike` подключает геометрию рамы из `bikes.py`: сдвиг седла по рельсам
пересчитывается в изменение высоты через реальный угол подседельной трубы,
а калибровать масштаб можно по базе велосипеда (оси колёс), не ловя ось педали.

`--calib x1,y1,x2,y2,мм` — две точки с известным расстоянием между ними
(ось каретки → ось педали = длина шатуна). Без калибровки выдаются только
направления регулировок, без величин. В веб-интерфейсе эти две точки
ставятся кликами прямо по загруженному фото (или первому кадру видео).

Видео обрабатывается по оборотам: период педалирования оценивается по
автокорреляции угла колена, в каждом обороте берутся НМТ/ВМТ, в отчёт идёт
медиана по всем оборотам, а разброс (MAD) между ними выводится отдельно —
большой разброс сам по себе признак раскачки таза или шумной детекции.

## Протокол съёмки — от него зависит 80% точности

Тот же протокол со схемами — в приложении, вкладка «Как снимать», там же кнопка «Скачать инструкцию PDF».

1. Велосипед на станке, строго вертикально (проверить отвесом/уровнем).
2. Камера **строго перпендикулярно** плоскости велосипеда, на высоте каретки,
   расстояние 2.5–3 м, зум вместо приближения (широкоугольник даёт до 5–7°
   ошибки на краях кадра).
3. Райдер в облегающей одежде, руки на привычном хвате, взгляд вперёд.
4. Разогреться 5–10 минут: холодная посадка отличается от рабочей.
5. Для фото: три кадра — шатун внизу вдоль оси подседельной трубы, шатун вверху,
   шатун горизонтально (для KOPS). Для видео: 10–15 с ровного педалирования
   на рабочем каденсе, 60 fps.

## Архитектура

```
bikefit/
  pose.py        детекция 33 точек (MediaPipe BlazePose), выбор ближней к камере стороны
  geometry.py    углы, калибровка масштаба, перевод градусов в миллиметры
  references.py  референсные диапазоны по дисциплинам (изолированы от логики)
  rider.py       антропометрия райдера: формулы высоты седла, ширина руля
  bikes.py       геометрия конкретных велосипедов (Rose Backroad L, …)
  analyzer.py    метрики -> отклонения -> правила рекомендаций
  report.py      разметка кадра + текстовый отчёт
  ui_calib.py    Streamlit-хелперы: калибровка кликами по фото
  guide.py       инструкция по съёмке и пояснение метрик: текст + SVG-схемы (UI и PDF)
  pdf_report.py  PDF-отчёт (reportlab): кадры, измерения, рекомендации
  cli.py         консольный интерфейс
app.py           Streamlit UI
```

Ключевое решение: угол переводится в миллиметры не эмпирическим
коэффициентом, а геометрически. Длины бедра и голени измеряются на этом же
кадре, расстояние таз↔педаль считается по теореме косинусов для текущего и
целевого угла, разница переводится в миллиметры через калибровку. То же для
локтя → длина выноса.

Порядок рекомендаций повторяет протокол живого фиттинга: стопа → высота
седла → вынос седла → кокпит. Менять кокпит раньше седла бессмысленно.

## Референсные диапазоны

Сведены из Holmes et al. (1994, угол колена в НМТ 25–35° сгибания),
Retül/Specialized Body Geometry, материалов Steve Hogg и обзора Silberman et al.
(2005). Значения между школами расходятся — таблица вынесена в
`references.py`, чтобы её можно было заменить под свою методику.

## Геометрия велосипедов

`bikes.py` хранит официальные таблицы производителей. Сейчас:

| Ключ | Велосипед | Stack / Reach | Подседельная | База | Рост |
|---|---|---|---|---|---|
| `rose_backroad_ml` | Rose Backroad карбон 2025, M/L (57) | 599.6 / 403.2 | 74° (эфф. 73.85°) | 1048.7 | 180–184 |
| `rose_backroad_l` | Rose Backroad карбон 2025, L (59) | 610.5 / 412.3 | 73.75° (эфф. 73.78°) | 1063.8 | 185–191 |
| `bianchi_impulso_comp_lg` | Bianchi Impulso Comp карбон, LG | 580 / 401 | 73.5° | 1045 | ~180–188 |

Rose маркирует размер и буквой, и «frame height» в см — в таблице указаны оба.
Длина шатуна, выноса и покрышка зависят от комплектации — для M/L вписаны
шатун 175 мм и покрышка 40 мм (наружный диаметр колеса ≈ 702 мм для калибровки).
Чтобы добавить велосипед, скопируйте `ROSE_BACKROAD_L` и впишите числа из
таблицы Frame geometry производителя.

## Что метод принципиально не видит

* **2D-проекция.** Отклонение камеры от перпендикуляра на 10° даёт ошибку угла
  в колене до 5–8°. Вальгус/варус колена во фронтальной плоскости не виден
  вообще — для этого нужен второй кадр спереди.
* **Статика вместо динамики.** По одному фото не видно раскачки таза, разницы
  между ногами, изменения посадки под нагрузкой. Видео решает это частично.
* **Точки — не суставы.** MediaPipe даёт центр «пятна» сустава, а не центр
  вращения. Систематический сдвиг маркера тазобедренного сустава на 1 см даёт
  ~2° в колене. Для клинической точности нужны физические маркеры.
* **Ось педали приближается серединой лодыжка↔плюсна**, реальная позиция
  зависит от установки шипов.

Отчёт — инструмент самонастройки и скрининга, а не замена очному фиттингу.
При боли в колене, пояснице или онемении рук нужен специалист.

## Дальше по roadmap

1. Второй ракурс (спереди) → трекинг колена во фронтальной плоскости, Q-фактор.
2. Автоопределение фазы шатуна через детекцию каретки и педали (YOLO на
   размеченном датасете) — уберёт требование ловить НМТ вручную.
3. Автокалибровка по колесу (Hough circles + известный ETRTO).
4. Проверка перпендикулярности камеры по расхождению левых/правых точек.
5. Персонализация диапазонов: тест подвижности (sit-and-reach, Thomas test) как
   входные данные, сдвигающие референс.
6. Хранение истории правок: что поменяли → как изменились углы и ощущения.
